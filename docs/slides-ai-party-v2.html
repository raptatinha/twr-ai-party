The 4Ds como base da aula

Framework de fluência em IA
  • Delegation: saber quais tarefas delegar e escolher o modelo adequado
  • Description: fornecer descrições claras com exemplos, arquivos e regras
  • Discernment: avaliar criticamente, validar com colegas e documentação
  • Diligence: evitar dados sensíveis, usar variáveis de ambiente, ser transparente
Conexão com o workshop
  • Delegation -> Agents, automações e escolha de modelos
  • Description -> prompts, rules, skills e contexto
  • Discernment -> QA, revisão critica e documentação oficial
  • Diligence -> segurança, .env, transparência em tickets
Pergunta: Qual dos 4Ds é mais difícil no seu contexto hoje?

Assistentes, Modelos e Context Management

Escolha de modelos
  • Cada modelo tem características e limitações próprias
  • Mesmo prompt gera resultados diferentes entre modelos
  • Leia a documentação do modelo antes de julgar qualidade
  • Cloud 4.6 Opus High, Sonnet, Codex, Gemini — cada um para um caso
Gerenciamento de contexto e tokens
  • /compact para preservar aprendizado essencial
  • /clear para trocar de tarefa sem poluição
  • Salvar informações importantes em arquivos evita alucinações
  • Tokens sao recurso finito — usar com critério
Regra prática: mude de assunto? limpe o contexto. Use arquivos intermediários para preservar aprendizado.

Bloco 02 · 10 min

MCP: o protocolo de conexão

O que é MCP
  • Padrão para IA conversar com ferramentas
  • Conecta modelo a recursos externos
  • Permite automação com contexto real
Usuario -> Assistente -> MCP Server -> Ferramenta
                   <- Resposta com contexto real

Sem MCP:
- Modelo responde só com contexto atual

Com MCP:
- Modelo acessa dados/ferramentas
- Fluxo fica mais acionável
Integrações demonstradas
  • Jira — criação de tickets e comentários
  • Slack — notificações automáticas
  • Playwright — automação de browser
  • Figma — análise de design

Comparativo técnico

MCP vs CLI vs Agents: 3 ferramentas, 3 propósitos

🔌
Playwright MCP
Servidor MCP para IDEs e assistentes
  • Protocolo que conecta LLMs ao browser
  • Opera via árvore de acessibilidade, não pixels
  • Ferramentas: navegar, clicar, preencher, screenshot
  • Ideal para explorar, investigar bugs e prototipar
  • Alto consumo de tokens (snapshots completos)
Cursor, VS Code, Claude Desktop
⚡
playwright-cli
CLI otimizada para coding agents
  • Comandos concisos: open, click, snapshot, fill
  • Token-eficiente — sem schemas grandes no contexto
  • Sessões persistentes com perfil de browser
  • Skills instaláveis para ampliar capacidade
  • Melhor para agents com janela de contexto limitada
npx playwright-cli open --headed
🤖
Playwright Test Agents
Pipeline de geração de testes com IA
  • Planner: explora app e gera plano em Markdown
  • Generator: transforma plano em testes Playwright
  • Healer: executa, diagnostica e corrige testes
  • Usam seed test como ponto de partida
  • Setup: npx playwright init-agents
Planner → Generator → Healer
Quando usar qual: MCP para explorar via IDE · CLI para agents que precisam economizar tokens · Agents para gerar suítes de teste completas automaticamente.

Bloco 03 · 25 min [DEEP]

Playwright MCP na prática

Como funciona
  • Servidor MCP que dá ao LLM ferramentas de browser
  • Opera via accessibility snapshots — não precisa de vision model
  • LLM lê a árvore, identifica refs e executa ações
  • Suporta navegação, clique, preenchimento, screenshots, tabs, network
Funcionalidades avançadas
  • browser_run_code: executa scripts Playwright completos
  • Network mocking: interceptar e mockar respostas de API
  • Storage state: salvar/restaurar cookies e localStorage
  • Modos: headed (padrão), headless, browser extension
Tokens: cada snapshot traz a árvore de acessibilidade completa. Ideal para loops iterativos curtos em IDEs, não para automação em massa.
Configuração (Cursor / VS Code / Claude Desktop):
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

Exemplo de snapshot retornado:
- heading "todos" [level=1]
- textbox "What needs to be done?" [ref=e5]
- listitem:
  - checkbox "Toggle Todo" [ref=e10]
  - text: "Buy groceries"

O LLM usa refs para interagir:
→ ref=e5 para digitar no campo
→ ref=e10 para marcar o checkbox

Opções de configuração:
--headless       (sem janela visível)
--browser=firefox (escolher browser)
--isolated       (sessão limpa)
--port 8931      (modo servidor HTTP)

Bloco 04 · 25 min [DEEP]

playwright-cli: automação para coding agents

O que é playwright-cli
  • CLI de browser projetada para coding agents (Claude Code, Copilot, etc.)
  • Comandos concisos que economizam tokens vs schemas MCP
  • Após cada comando, retorna snapshot com refs
  • Sessões persistentes — cookies e estado preservados
  • Skills instaláveis: playwright-cli install --skills
MCP vs CLI — quando usar cada um
  • MCP: IDEs com loops iterativos (Cursor, VS Code, Claude Desktop)
  • CLI: coding agents que precisam de eficiência de tokens
  • CLI evita carregar schemas grandes no contexto
  • Ambos controlam o mesmo browser — escolha pelo ambiente
# Instalar e usar
npm install -g @playwright/cli@latest

# Fluxo típico
playwright-cli open https://exemplo.com --headed
playwright-cli snapshot
playwright-cli fill e5 "teste@email.com"
playwright-cli click e12
playwright-cli screenshot

# Navegação e interação
playwright-cli type "texto livre"
playwright-cli press Enter
playwright-cli select e20 "opcao"
playwright-cli hover e15

# Sessões nomeadas
playwright-cli -s=login open https://app.com
playwright-cli list

# Monitoramento visual
playwright-cli show

# DevTools
playwright-cli console
playwright-cli eval "document.title"
playwright-cli network
Diferença-chave: MCP é um servidor de protocolo para IDEs. CLI é uma ferramenta de linha de comando para agents. Ambos usam Playwright por baixo.

Bloco 05 · 15 min [DEEP]

Playwright Test Agents: Planner → Generator → Healer

🎭 Planner
  • Explora a aplicação navegando ao vivo
  • Gera plano de teste em Markdown (specs/)
  • Recebe um seed test como ponto de partida
  • Opcionalmente recebe PRD para contexto
  • Saída é legível e editável por humanos
🎭 Generator
  • Lê o plano Markdown e gera testes em tests/
  • Verifica seletores e assertions ao vivo
  • Usa catálogo de assertions do Playwright
  • Cada spec → arquivo de teste correspondente
  • Pode gerar erros iniciais que o Healer corrige
🎭 Healer
  • Executa teste que falhou e inspeciona a UI atual
  • Propõe patch: locator, wait, dados
  • Reexecuta até passar ou skipa se o bug é da app
  • Guardrails impedem loop infinito
  • Tende a corrigir o teste, não a encontrar bugs
Setup: npx playwright init-agents --loop=vscode (ou --loop=claude). Precisa de seed test + objetivo claro. Sempre revise o plano antes de gerar.

Bloco 06 · 25 min [DEEP]

Cursor Deep Dive

Cursor Rules
  • Padronizam comportamento do assistente
  • Carregadas automáticamente por tipo de arquivo
  • Reduzem retrabalho entre pessoas do time
  • Garantem consistência de output
Cursor Skills
  • Conjuntos de instruções executadas sob demanda
  • Reuso de playbooks recorrentes
  • Acelera tarefas operacionais de alto volume
  • Facilita onboarding de novos membros
Comparação da demo:
Sem rule:
- resposta inconsistente
- formato variável

Com rule + skill:
- saída previsível
- qualidade mais estável
- tempo menor de revisão

Diferença-chave:
Rules = automática por contexto
Skills = acionada sob demanda
Agents = executores que usam ambos

Bloco 06 · continuação

Skills, Rules e Agents: diferenças

Skills
  • Instruções executadas sob demanda
  • Transferem conhecimento humano para arquivos reutilizáveis
  • Evoluem conforme necessidade do projeto
  • Podem ser globais ou por contexto
Rules
  • Carregadas automáticamente por tipo de arquivo
  • Definem padrão de comportamento
  • Convenções de teste, fixtures, autenticação
  • Essenciais para consistência de time
Agents
  • Entidades executoras que acionam skills/rules
  • Gerenciam checkout e check-in de skills
  • Reduzem consumo carregando só o necessário
  • Sobreposição de conceitos é normal
Dica: use agentes para gerenciar skills, reduzindo tokens ao carregar apenas o necessário para cada contexto.

Bloco 08 · 10 min

Skills na prática: Dashboards e Observabilidade

Casó real: ClickHouse + Grafana
  • Skills acessam ClickHouse para queries automáticas
  • Geram dashboards JSON e publicam via API no Grafana
  • Antes: semanas para criar dashboards manualmente
  • Agora: horas com automação via skills
Framework honeydoo (wrapper Playwright)
  • Coleta dados antes, durante e após execução
  • Armazena em múltiplas tabelas no ClickHouse
  • Notificações automáticas via Slack
  • Abertura de tickets no Jira em caso de falha
Fluxo de dados:
Testes (honeydoo/Playwright)
  -> Coleta métricas (antes/durante/depois)
  -> ClickHouse (armazenamento)
  -> Skills (queries automáticas)
  -> Grafana (dashboards via API)

Exemplos de dashboards:
- Monitoramento de runs de testes
- Taxa de falhas com alertas automáticos
- Tempo de execução por suite
- Diagramas de entidades do banco

Cultura

Adoção de IA e cultura de inovação

Como funciona na prática
  • Autonomia dos times para criar skills e pipelines próprios
  • Cotas para ferramentas como Cursor e Claude Code
  • Incubadora interna para projetos inovadores
  • Skills criadas para um time rápidamente adaptadas por outros
Compartilhamento de conhecimento
  • Repositório centralizado de skills e projetos
  • Múltiplos canais de comúnicação e eventos internos
  • Disseminação rápida de novas tecnologias
  • Ambiente dinâmico com adaptação constante
Insight: incentivo institucional + autonomia dos times = aceleração da adoção.

Qualidade

Produtividade e qualidade com IA

Foco em qualidade, não em métricas
  • Aumento percebido de produtividade, mas sem métricas precisas
  • Experimentação constante dificulta estabelecer baseline
  • Foco atual: qualidade dos resultados
  • Mensuração pode vir em fases futuras com processos mais estáveis
Importância da arquitetura
  • IA não substitui boa arquitetura de testes
  • Page Object Model, separação de responsabilidades
  • Facilita manutenção mesmo com automação por IA
  • Padrões consistentes = IA mais eficiente
Sem boa arquitetura: IA gera código rápido, mas manutenção fica cara.

Boas práticas

Boas práticas para automação com IA

Revisão e validação humana
  • Revise planos, skills e testes gerados pela IA
  • Adapte ao contexto do projeto
  • Não confie cegamente em resultados automáticos
  • Valide com colegas e documentação oficial
Gerenciamento eficiente de tokens
  • Arquivos intermediários para preservar conhecimento
  • Compactação de contexto quando conversa ficar longa
  • Carregar apenas skills necessárias por contexto
  • Escolha critériosa de informações para a IA
Mindset: cenário em evolução constante — experimente, adapte e compartilhe aprendizados.
